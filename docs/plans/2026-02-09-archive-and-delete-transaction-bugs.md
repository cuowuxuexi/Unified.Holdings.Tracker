## 1. 目标与范围

本次修复覆盖两个问题：

| Bug                            | 优先级 | 影响                                 |
| ------------------------------ | ------ | ------------------------------------ |
| 恢复存档后页面仍显示“最新状态” | P1     | 用户误判恢复失败，数据可信度下降     |
| 删除交易后现金/杠杆不一致      | P1     | 杠杆账户状态错误，影响后续交易与统计 |

## 2. Bug 1：恢复存档后显示错误状态

### 2.1 根因（修订后）

原计划只关注备份文件缓存，但实际是“双层缓存问题”：

1. `DataService` 对备份索引和备份文件有 5 分钟内存缓存。
2. 恢复备份后，投资组合详情缓存（`portfolio:{id}` / `portfolios:list`）和统计缓存未失效，前端读取到恢复前旧数据。

### 2.2 修复策略

1. 增加文件级缓存清理接口：`dataService.clearCache(relativePath)`。
2. 读取备份前强制失效：
   - `backups/index.json`
   - 目标备份文件路径
3. 恢复完成后统一失效业务缓存：
   - `portfolio:{id}`
   - `portfolios:list`
   - 统计缓存（`portfolioStatsService.clearCache(id)`）

### 2.3 已实施修改

- `packages/infra/src/data/data-service.ts`
  - 新增 `clearCache(relativePath)`。
- `apps/backend/src/services/backupService.ts`
  - `getBackup`：读取前清理索引和备份文件缓存。
  - `restoreBackup` / `restoreBackupSmart`：恢复成功后清理组合与统计缓存。

### 2.4 验收标准

- [ ] 创建 A、B 两个备份，恢复 A 后立即读取组合详情，返回 A 的交易数与现金。
- [ ] 紧接着恢复 B，立即读取详情，返回 B 的状态。
- [ ] 全局恢复（smart restore）同样命中最新恢复结果。

## 3. Bug 2：删除交易后现金/杠杆不一致

### 3.1 根因（修订后）

旧逻辑是“按单条交易反向扣回”，存在结构性问题：

1. BUY 删除逻辑未以交易记录的真实口径重建状态。
2. SELL / DIVIDEND 删除中对已是 CNY 的 `amount` 再次换算。
3. 删除中间交易时，仅做局部回滚，未重放后续交易，容易累计偏差。

### 3.2 修复策略（已落地）

将删除流程改为“删除后重放剩余交易”，不再依赖单条反向推导：

1. 先在内存中去除目标交易。
2. 基于持久化交易（优先使用落库 CNY 金额）按时间顺序重放现金/杠杆。
3. 以一次数据库事务完成：
   - 删除交易记录
   - 更新组合现金与杠杆

核心约束：

- 重放阶段不再调用实时汇率接口，优先使用交易落库 `amount/exchangeRate`。
- 事务化更新，避免“交易删了但组合状态未更新”的半成功状态。

### 3.3 已实施修改

- `packages/infra/src/storage/storage.prisma.ts`
  - 新增交易重放辅助函数（金额/手续费口径解析、初始杠杆推导、状态重放）。
  - `deleteTransactionFromPortfolio` 改为删除后重放并事务更新。
  - 删除逻辑不再直接调用外部汇率服务。

### 3.4 当前约束与风险

为兼容现有模型，本次重放默认组合初始杠杆使用额为 `0`（当前创建入口与业务流程一致）。  
若历史数据来自外部导入且初始 `usedAmount` 非 0，需单独补历史校正脚本。

### 3.5 验收标准

- [ ] 无杠杆：BUY/SELL 添加后删除，现金回到删除前。
- [ ] 有杠杆：SELL 触发还杠杆后删除，`cash/used/available` 同步回退。
- [ ] 外币交易：删除 SELL/DIVIDEND 不再出现重复汇率换算。
- [ ] 删除中间交易：删除后组合状态与“从初始重放剩余交易”一致。
