# 项目任务分解规划：格隆汇与Seeking Alpha数据获取方案

## 已明确的决策

- **法律底线**：任何技术方案必须遵守《网络安全法》《网络数据安全管理条例》《个人信息保护法》和《反不正当竞争法》
- **技术约束**：运行环境为Windows 11 + PowerShell
- **现有工具**：优先使用现有工具（WebFetch、exa web search、open-websearch）组合
- **合规原则**：禁止非法侵入网络、干扰服务正常运行、窃取个人信息

---

## 整体规划概述

### 项目目标

设计一套**合法合规**的财经数据获取方案，在尊重网站服务条款和技术防护的前提下，获取格隆汇和Seeking Alpha的公开财经信息（财报分析、投资观点等），避免法律风险和技术对抗。

### 技术栈

- **现有MCP工具**：exa web search、open-websearch、WebFetch
- **合法替代方案**：RSS订阅、官方API（如存在）、公开数据集
- **技术调研工具**：Playwright浏览器自动化（仅用于测试，非生产环境）

### 主要阶段

1. **法律与技术边界研究**（风险评估与合规性分析）
2. **合法数据获取方案设计**（官方渠道、替代数据源、工具选型）
3. **技术实现与测试**（在合规前提下的小规模验证）
4. **长期维护与风险监控**（合规性监测、反馈机制）

## 详细任务分解

### 阶段1：法律与技术边界研究

#### 任务1.1：法律合规性评估

- **目标**：明确当前中国法律框架下网络爬取的合法边界
- **输入**：《网络数据安全管理条例》第18条、《反不正当竞争法》第13条、相关司法判例
- **输出**：法律合规性评估报告（Markdown文档）
- **涉及文件**：`docs/legal-compliance-report.md`（新建）
- **预估工作量**：2-3小时（包括法律条文检索与案例分析）

**关键法律要点**：

- ✅ **允许**：访问公开数据（无需登录、无robots.txt禁止）
- ✅ **允许**：正常频率的HTTP请求（不干扰服务器）
- ❌ **禁止**：破坏技术保护措施（如绕过Cloudflare人机验证）
- ❌ **禁止**：大规模爬取导致服务器负载异常
- ❌ **禁止**：获取个人隐私信息或商业机密

#### 任务1.2：目标网站技术防护分析

- **目标**：识别格隆汇和Seeking Alpha的反爬虫机制类型
- **输入**：两个网站的robots.txt、网络请求头、响应状态码
- **输出**：反爬虫技术分析文档（包含User-Agent检测、JavaScript挑战、频率限制等）
- **涉及文件**：`docs/anti-scraping-analysis.md`（新建）
- **预估工作量**：3-4小时

**技术调研方法**：

1. 使用`mcp__Playwright__browser_navigate`访问两个网站
2. 使用`mcp__Playwright__browser_network_requests`分析网络请求
3. 使用`mcp__Playwright__browser_console_messages`查看JavaScript日志
4. 记录403错误、验证码、JavaScript混淆代码等防护措施

#### 任务1.3：官方API与服务条款调研

- **目标**：调研两个网站是否提供官方数据接口或合作方式
- **输入**：格隆汇官网、Seeking Alpha开发者文档、第三方金融数据API平台
- **输出**：官方数据获取渠道清单（包含API费用、限制、覆盖范围）
- **涉及文件**：`docs/official-api-options.md`（新建）
- **预估工作量**：2-3小时

**调研方向**：

- 格隆汇是否提供企业级API服务（查阅"勾股大数据"产品）
- Seeking Alpha Premium API或Alpha Vantage等第三方接口
- 是否有公开的RSS Feed或邮件订阅服务

### 阶段2：合法数据获取方案设计

#### 任务2.1：方案一——使用现有MCP工具组合

- **目标**：利用`exa web search`和`open-websearch`获取搜索引擎索引的公开数据
- **输入**：目标关键词（如"格隆汇 某公司财报分析"、"Seeking Alpha stock analysis AAPL"）
- **输出**：搜索结果JSON数据、内容摘要、原文链接
- **涉及文件**：
  - `packages/infra/src/providers/financial-news-provider.ts`（新建）
  - `apps/backend/src/services/newsAggregationService.ts`（新建）
- **预估工作量**：4-6小时

**技术实现要点**：

- 使用`mcp__exa__web_search_exa`搜索特定股票代码+网站域名
- 使用`mcp__open-websearch__fetchGithubReadme`（类似逻辑）抓取文章摘要
- 避免直接访问目标网站，依赖搜索引擎缓存
- 遵守Google/Bing的robots协议

**优点**：

- 完全合法（使用公开搜索引擎）
- 无需处理反爬虫机制
- 工具成熟稳定

**缺点**：

- 数据更新延迟（搜索引擎索引周期）
- 无法获取付费内容或登录后内容
- 搜索结果可能不完整

#### 任务2.2：方案二——订阅RSS/邮件通知

- **目标**：通过RSS Feed或邮件订阅获取增量更新
- **输入**：格隆汇RSS地址（如存在）、Seeking Alpha RSS Feed
- **输出**：RSS解析器、邮件监听服务
- **涉及文件**：
  - `packages/infra/src/providers/rss-feed-provider.ts`（新建）
  - `apps/backend/src/services/rssSubscriptionService.ts`（新建）
- **预估工作量**：3-5小时

**技术实现要点**：

- 使用`rss-parser`库解析RSS Feed
- 配置邮件监听（IMAP协议）
- 定时轮询（每小时1次）

**优点**：

- 官方支持的数据获取方式
- 数据实时性较好
- 完全合法合规

**缺点**：

- 依赖网站是否提供RSS服务
- 内容可能仅为摘要，需跳转原文

#### 任务2.3：方案三——第三方金融数据聚合平台

- **目标**：使用合法的第三方财经数据API（如Wind、同花顺、Bloomberg API）
- **输入**：API密钥、查询参数（股票代码、时间范围）
- **输出**：标准化的财报数据、研报摘要
- **涉及文件**：
  - `packages/infra/src/providers/third-party-data-provider.ts`（新建）
  - `docs/third-party-api-comparison.md`（新建）
- **预估工作量**：6-8小时（包含调研、对接、测试）

**推荐平台**：

- **国内**：巨潮资讯（官方披露平台）、天眼查API、聚合数据
- **国际**：Alpha Vantage、Finnhub、Polygon.io

**优点**：

- 数据质量高、结构化
- 合法合规、有服务协议保障
- 覆盖范围广（可能包含更多数据源）

**缺点**：

- 通常需要付费
- 数据格式需要适配
- 可能无法获取特定网站的独家观点

## 附录：关键法律条文摘录

### 《网络数据安全管理条例》第18条

> 网络数据处理者使用自动化工具访问、收集网络数据，应当评估对网络服务带来的影响，**不得非法侵入他人网络，不得干扰网络服务正常运行**。

**解读**：允许自动化工具访问，但需评估影响，禁止破坏性行为。

### 《反不正当竞争法》第13条

> 经营者不得以**欺诈、胁迫、避开或者破坏技术管理措施**等不正当方式，获取、使用其他经营者合法持有的数据。

**解读**：禁止绕过技术防护措施（如Cloudflare验证、登录墙）。

### 《个人信息保护法》第27条

> 个人信息处理者可以在**合理的范围内**处理个人自行公开或者其他已经合法公开的个人信息；**个人明确拒绝的除外**。

**解读**：公开信息可处理，但需遵守"合理范围"和"明确拒绝"原则。
