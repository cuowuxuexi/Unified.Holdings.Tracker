## 📋 修订说明

### 核心问题
美股交易时间在北京时间次日凌晨收盘（4:00-5:00），导致数据获取时机问题：

- **周五基准问题**：美股周五交易在北京时间周六凌晨才收盘，如果用户周六早上打开应用，周五数据可能还未更新完成
- **月末基准问题**：月末最后一天的美股数据，要到次日凌晨才能获取

### 解决方案

#### 周度收益
- **修改前**：基准日 = 上周五（`getLastWeekFridayDate`）
- **修改后**：基准日 = 上周六（`getLastWeekSaturdayDate`）
- **理由**：用户通常在周一或之后查看周度收益，此时上周六数据（包含周五美股）已稳定可获取

#### 月度收益
- **基准日**：上月最后一天（保持不变）
- **数据获取**：依赖现有的智能回退机制（fallback）
  - 如果月末当天数据未就绪，自动回溯到前一个交易日
  - 系统记录回退天数（`fallbackDays`）
  - 前端可显示实际使用的基准日期

### 修改1：周度基准日计算函数

**文件**：`apps/backend/src/services/calculationService.ts`

**位置**：第 45-51 行

```typescript
// 修改前
function getLastWeekFridayDate(today: Date): Date {
  const dayOfWeek = today.getDay(); // 0=周日
  const daysSinceMonday = (dayOfWeek + 6) % 7; // 周一=0
  const daysToLastFriday = daysSinceMonday + 3;
  return subDays(today, daysToLastFriday);
}

// 修改后
function getLastWeekSaturdayDate(today: Date): Date {
  const dayOfWeek = today.getDay(); // 0=周日, 6=周六
  // 计算距离上周六的天数
  // 周日(0)→1天, 周一(1)→2天, 周二(2)→3天, ..., 周六(6)→7天
  const daysToLastSaturday = dayOfWeek === 0 ? 1 : dayOfWeek + 1;
  return subDays(today, daysToLastSaturday);
}
```

**验证示例**（今天 = 2025-11-17，周一）：
- `dayOfWeek = 1`
- `daysToLastSaturday = 2`
- 结果：2025-11-15（上周六）✅

## 💡 关键设计决策

1. **为何选择周六而非周五**
   - 用户通常周一及之后查看周度收益
   - 周六数据包含了完整的周五美股行情
   - 避免数据更新延迟导致的查询失败

2. **为何月度不用倒数第2天**
   - 会丢失最后一天的收益数据
   - 现有代码已有智能回退机制（fallback）
   - 用户一般不会在月初立即查看上月收益

3. **智能回退机制的作用**
   - 自动处理节假日、周末、数据延迟等情况
   - 记录实际使用的日期和回退天数
   - 前端可透明展示给用户
